# Kit v3.0.0

Kit v3.0.0 is the capability-aware subagent-orchestration major release.

## Breaking Changes

- The Go module and direct install path are now
  `github.com/jamesonstone/kit/v3`.
- `kit dispatch` and `kit pr fix` no longer accept `--max-subagents`.
- Fixed three-lane defaults and four-lane ceilings are removed. The active host
  owns runtime capacity and scheduling.

`--single-agent` remains supported. GitHub repository, release, registry, and
API URLs remain `github.com/jamesonstone/kit` without a major-version suffix.

## Orchestration Contract

- The existing `agent-team-orchestration` rule negotiates only host-confirmed
  child execution, parallelism, stable references, follow-ups, model and effort
  selection, waiting, fresh verification, and effective capacity.
- Provider-neutral profiles map against the live host roster. Current Codex,
  Claude, Copilot, and Warp/Oz examples are illustrative TOOLING guidance, not
  pinned policy.
- Only the accountable root supervisor launches children. Continuity,
  requested and effective profiles, actual versus logical lanes, achieved
  parallelism, verification independence, and degradation are reported
  literally.
- Kit remains prompt-only and never selects a model, launches a child, or
  supervises execution.

## Release Boundary

The first qualifying main release selects `v3.0.0`; later releases increment
the latest v3 patch. Quality gates run before tag creation. A qualifying tag
already attached to the same SHA is reused for idempotent publication recovery,
while conflicting or ambiguous tags fail closed and are never moved.

Release ownership is deliberately split. Kit keeps the exact v3 selector,
quality gates, GoReleaser builds and checksums, and idempotent artifact upload.
`jamesonstone/mint@v0.2.1` owns immutable Git tag and GitHub Release creation or
reuse. Publication and recovery remain in the main workflow instead of relying
on a workflow-token tag push to trigger a second workflow.

The main release workflow ignores a `.kit.yaml`-only provenance merge so a
post-release source-commit update cannot silently allocate `v3.0.1`. That
provenance update remains a separate issue and ready pull request with its own
merge authorization.

## Upgrade

Use `kit upgrade` from v2.0.6 or install directly with:

```bash
go install github.com/jamesonstone/kit/v3/cmd/kit@latest
```

Then run `kit version`, preview `kit reconcile --include-files --dry-run
--diff`, apply reviewed guidance, and run `kit check --project`. See the
[v3 migration guide](../migration-v3.md) for the complete sequence.
